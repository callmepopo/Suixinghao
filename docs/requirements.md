# 需求与验收

## 范围

随行号以用户自建Unraid+模块为服务端，网页做基础电话和Key测试，iOS为最终使用入口；源码、部署方式、驱动引用和接口契约公开。HiDeck与第三方驱动保持各自许可。App不携带个人服务地址、网页密码或Key，用户手工配置自己的HTTPS根地址及独立App Key。

首版维持单模块、单通话，不提供公共电话托管、多人并发、任意AT代理、通用模块一键开通或App Store推送relay。网页短信完整收发沿用HiDeck原入口；内嵌网页集中电话测试与Key管理。

## 验收清单

| 层级 | 必须通过的场景 | 不能替代的后续验收 |
|---|---|---|
| 公开材料 | README入口、模块分类、引用/许可清楚；示例无个人数据；公开构建不依赖private/hideck | 不等于许可允许任意商用 |
| 本地服务 | Go race/vet；Key生成/摘要存储/撤销/隔离；电话ID与所有权、白名单、PCM/SSE、短信分页/已读、历史去重/缺口 | 不等于模块在线或运营商接续 |
| 部署脚本 | bash/sh语法、XML/Compose形状；环境可配置；目标缺失/内核不符拒绝；无驱动二进制分发 | 静态检查不执行硬件写入 |
| 新Unraid部署 | HiDeck healthy、模块可用、SIM注册、鉴权、Key撤销；7581受反代保护；重启后恢复 | 健康接口不能证明听感 |
| iOS本地 | 演示/无预置地址Key；HTTPS校验、Keychain；模拟接口、控制、声音策略；模拟器编译 | 不等于签名/真机/锁屏 |
| 开发签名手机测试 | 新App重新配置，核验新版后按授权处理旧身份；短信单次真实收发/已读；呼出/来电双向声音、静音恢复、听筒/扬声器、DTMF、挂断/断网恢复 | 开发APNs sandbox不证明生产推送 |
| 正式候选包 | production APNs的TestFlight，新身份，至少2分钟锁屏双向通话、来电接听及短信提醒；强退/弱网/后台边界记录 | TestFlight不代表App Store审核通过 |
| 公开发布 | 手机验收成功才合main/tag；同一正式构建TestFlight后提交美区审核；GitHub Release对应源码标签与构建证据 | 版本号一致不证明商店包字节一致 |

联系人、号码、短信正文、卡片/模块标识、Key和推送令牌只在已授权本地功能中使用，测试报告用合成数据或结果状态。真实电话/短信必须限目标、次数和时间，不使用循环重试。启用录音需要通话参与者同意，公开安装示例关闭录音。

## 日常测试与状态记录

流程为AI在同一源码仓库develop开发 → private/testing保存开发签名包、私有配置及手机验收记录 → 手机验收通过后合main → 正式Release候选包TestFlight production验证 → 同一正式构建美区审核与对应GitHub Release。private是隐私分类，不能把它等同测试分支；不维护private内第二份源码。旧archive/legacy只读回退，后续实现只改公共源码仓库。

每批记录版本、源码commit、测试层级和结果，分别写“编译/模拟器/模拟接口/新部署/开发真机/TestFlight/商店审核”。202610094初始批次为开源整理及本机静态/构建验证，不包含签名真机安装、线上变更、真实拨号/短信、production推送或上架验收。实际检查结果见根CHANGELOG，不预填未运行项目为通过。

自行签名需使用匹配的Apple注册身份与描述文件。新身份开发签名装机和前台接入已验证，真实通话及锁屏仍待验证；旧身份的功能结果不能直接继承。正式商店版自建服务的锁屏推送仍依赖未实现relay，发布范围必须据此调整；见 [App Store后续](app-store.md)。
