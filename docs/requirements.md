# 需求与验收

## 范围

随行号以用户自建Unraid+模块为服务端，网页做基础电话和Key测试，iOS为最终使用入口；源码、部署方式、驱动引用和接口契约公开。HiDeck与第三方驱动保持各自许可。App不携带个人服务地址、网页密码或Key，用户手工配置自己的HTTPS根地址及独立App Key。

首版维持单模块、单通话，不提供公共电话托管、多人并发、任意AT代理、通用模块一键开通；App Store推送relay已有独立Production／Sandbox部署；开发包Sandbox锁屏来电已验，Production／TestFlight未验。网页短信完整收发沿用HiDeck原入口；内嵌网页集中电话测试与Key管理。

## App0.1.10：锁屏免提、车载蓝牙与项目帮助

范围为App音频路由与设置页面，服务仍为0.1.5/build6。问题反馈：锁屏接听后系统免提自动回退；车机可播放手机音乐，但随行号接听后声音留在手机。根因尚无车载现场日志，不将候选修复等同真机解决。

- CallKit激活后，若仍在听筒且用户未指定路由，尝试选择已连接HFP设备；多个HFP设备时优先匹配此前播放音乐的设备，无法唯一确定则保留系统选择。音乐A2DP连通不等于车机支持HFP。
- 通话页“声音设备”列出扬声器、手机听筒及系统可用输入设备，显示实际声音出口；已断开的设备选择失败只提示，不直接挂断。
- 路由/硬件格式变化后重建采音tap及8kHz转换器，恢复播放，保留通话所有权、WebSocket、接通状态、静音及等待音。旧采音与播放回调不进入新路由/新通话；蓝牙断开尝试使用系统回落路由。0.1.10原候选在恢复失败时结束通话；0.1.11按下文回归修复调整为保留通话、明确声音异常并允许重试。
- 设置页在未连接状态也能打开GitHub项目及Issues，无需进入关于页；公开项目地址独立于具体构建源码链接，不自动携带配置、号码或日志。

验收：锁屏接听后开/关系统免提并持续双向通话；车机音乐→来电接听→车载双向声音；通话中车机/听筒/扬声器往返；蓝牙断开/重新连接、静音切换、接通前切换、连续两通及挂断后不重启旧音频；SE3与15Pro设置项目链接可见可打开。离线路由状态与实际恢复代码替身检查、模拟器编译不替代真机/车机验收。


## App0.1.11：AirPods切换误挂断回归修复

15Pro使用0.1.10/build41，连接AirPods拨打电话，选中声音设备后挂断，用户反馈可能任意选项均触发。记录为真机验收失败。三份同版本现场崩溃均定位到AVAudioEngine安装采音tap时抛异常；旧节点格式与切换后的硬件格式不一致是代码支持的原因假设，报告未包含具体断言文本。不能将其写成唯一根因或所有设备实证。

代码存在两条主动结束路径：音频中断开始、路由恢复耗尽；CallKit重复激活又被首次媒体启动条件拦截。本轮解除音频异常与电话挂断的耦合：中断暂停采音/播放，保持远端通话与WebSocket，CallKit重新激活后恢复原通话且不重复拨号/接听；中断期间不自行激活CallKit会话。恢复仍有次数上限，失败明确展示声音异常并提供“重试声音”，用户可换回原设备或手动挂断。不得把保留通话描述为双向声音已恢复。

同一已选HFP设备不重复切换；选择外设不无条件先切到默认路由。接通前上行、静音、旧采音/旧回调隔离要求继续保持。真实系统结束、对方挂断及传输断开仍沿原终止流程。

验收新增：AirPods拨号接通前/接通后选AirPods、听筒、扬声器不主动挂断；切换内同步中断与CallKit恢复；真实系统中断等待恢复、静音不泄漏、恢复失败有明确提示且可重试、重复激活不重复发起通话。0.1.11/build42仅完成中断兜底，未分发；后续build43处理采音崩溃，仍待15Pro复测。验收必须包括不崩溃、不挂断、实际双向有声，不能仅以通话状态保留记通过。

采音修复：输入/硬件格式变化时停旧引擎并创建新引擎；tap继承总线格式，不强制写入旧outputFormat；转换器按实际buffer.format更新。iOS 27使用支持错误返回的tap接口。回归覆盖旧节点输出格式滞留、设备往返、新旧引擎隔离，以及真实AVAudioConverter对16/24/44.1/48kHz输入连续转换的帧长和有效音量。

2026-10-14追加：用户确认build43 AirPods→扬声器成功，切听筒仍停留原通道。build44选择输入同时核对preferredInput和currentRoute；扬声器虽使用builtInMic，仍须覆盖之前的HFP优先输入，避免异步清除扬声器覆盖后回到旧设备。模拟用例须先在build43源码上失败、修复后通过，并覆盖扬声器→听筒、HFP→听筒及往返。实际听筒输出和双向声音仍需真机复测。

2026-10-14继续：用户补充选择听筒时页面显示听筒，实际仍在AirPods或扬声器，明确为蓝牙新增导致的既有功能回归。build45将显示/勾选与选择意图区分：输出端为builtInReceiver才勾手机听筒，输入端为builtInMic不能当成成功。选择听筒先设置手机输入，再解除输出覆盖（包括从HFP开始），去除defaultToSpeaker；路由输出变化及引擎停机重建完整音频引擎，不仅按输入格式判断。

新增验收：输入手机麦克风、输出仍HFP时显示/勾选仍为外设；输出仍扬声器时不能显示听筒。设备选择300/800/1700ms核验输出，仅一次补偿；系统拒绝时明确提示，声音引擎恢复不得清除此提示，“重试声音”重新申请原目标。新的设备选择、拔除设备、挂断或新通话须取消旧核验，系统后续选择仍按真实输出显示。普通听筒↔扬声器、AirPods→两者及往返、静音、中断恢复都要验。系统报告的输出不能代替实际双向有声验收。

2026-10-14 build45明确验收失败：真机记录中Speaker在引擎恢复前已被提前确认，重建新AVAudioEngine后回到BluetoothHFP；听筒选择也一直留在HFP。build46撤回整引擎重建及核验任务的自动二次选择写入，保持原I/O单元，自动mixer→output连接在重启时跟随硬件；采音tap仍为nil格式、转换器按buffer格式适配。CaptureLease更新代号以丢弃在途旧帧而保留原tap，退役旧通话后不接受回调。
