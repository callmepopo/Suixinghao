# 自动开通官方 App 推送

用户在自己的NAS上提供电话／短信服务，安装发布者的官方App，通过发布者的中继获得锁屏来电与短信提醒。手机的电话控制、短信正文和音频仍直接连接用户NAS，中继不承担网络穿透。用户不需要个人VPS或Apple开发者账号，不需要向发布者领取或手工复制中继凭据。

当前版本：App0.1.9（TestFlight构建40），NAS服务0.1.5（build6）。维护者15Pro开发包与SE3正式TestFlight整体测试已通过；自动模式NAS的真实App Attest绑定和锁屏接听仍是本轮外部测试重点，不因整体反馈宣称逐项通过。2026-10-13外部构建已关联既有网友测试组并提交Apple Beta审核，当前WAITING_FOR_BETA_REVIEW，批准后才可由外部测试员安装；旧0.1.8/build37保留。

## 开通前的条件

| 条件 | 谁负责 | 怎么确认 |
| --- | --- | --- |
| 兼容的NAS、DJI模块及SIM | 用户 | 按[硬件说明](hardware.md)核对环境；先完成网页电话／短信基础验证。本项目目前主要验证在特定Unraid／Linux amd64基线，不承诺所有NAS兼容 |
| 安装并运行NAS服务0.1.5 | NAS管理员 | 更新自有服务二进制及部署材料；先备份、确认电话空闲，升级后核对服务版本与模块状态 |
| 有效HTTPS根地址，手机能访问NAS | 用户 | 域名、证书与反代由用户维护；手机在实际使用网络可连接。推送中继不会替用户解决NAS外网可达性 |
| 安装官方App0.1.9／build40 | 手机用户 | 从已获批准的TestFlight测试组安装，后续使用匹配官方商店版本；自行签名且属于其他App身份的包不能作为官方应用证明 |
| 每部手机独立业务App Key | NAS管理员 | 在NAS的App接入管理页签发，手机连接时填写；多机共用业务Key可能覆盖推送登记，不要与中继授权混用 |
| 匹配环境的完整中继URL | NAS管理员 | 按发布者提供的官方入口配置；TestFlight／商店用Production，开发包用Sandbox，不能混配。例子见[环境样例](../deploy/unraid/examples/relay-client.env.example)，示例域名不是可用入口 |
| 发布者已开启对应环境自动开通 | 发布者 | 中继必须配置固定App身份、有效APNs授权及App Attest验证；用户不填写发布者Apple私钥或App ID参数 |
| NAS可出站访问中继、双方时间正确 | NAS管理员／发布者 | HTTPS请求可达；签名请求容许约60秒时钟偏差，设备时钟错误会导致拒绝 |
| 手机支持并能完成App Attest验证 | 手机用户 | App开通确认时自动验证。模拟器不能替代真机，不支持或验证失败会提示并拒绝自动签发，已有手工接入方式仍保留 |
| NAS管理员主动申请并由手机确认 | NAS管理员／手机用户 | 仅安装App不会自动授权任意服务器；管理员申请产生10分钟有效的请求，手机连接该NAS后确认 |

## 首次开通步骤

1. NAS管理员完成服务与HTTPS部署，配置匹配环境的完整中继URL。新部署采用自动模式时，不设置该环境的手工中继Key文件路径。
2. 登录NAS网页的“App接入”管理页，选择“TestFlight／App Store”环境，填写登记昵称，点击“申请开通推送”。昵称用于签发记录，不要求真实姓名或邮箱，不会自动匹配TestFlight邮箱。
3. 在官方App设置中连接这套NAS，使用该手机的独立业务App Key。进入“锁屏推送”，刷新状态，核对登记昵称，然后点击“确认为此NAS开通推送”。
4. VPS核验NAS实例签名及官方App证明后，NAS自动领取并私有保存中继授权；手机不接收后端凭据，不需要复制Key。
5. 分别确认手机显示“手机推送已登记”和“中继已授权”，再验证一次真实锁屏来电、接听／双向声音和短信提醒。两个状态都成功也不证明实际送达。

同一NAS可服务多部手机，只需一把实例中继授权；每部手机仍使用独立业务App Key。不同NAS分别授权。NAS实例文件要备份并保持私有，不把它放网页目录或公开仓库。

## 已有手工凭据怎么处理

旧手工凭据继续优先使用，升级不会自动替换、撤销或触发迁移。配置了对应环境手工Key路径时，App和管理页显示“使用既有手工中继授权”。

如需测试自动模式，NAS管理员先备份原配置与Key，在电话空闲时明确移除所选环境的手工Key路径，保留正确中继URL并重启自己的业务服务，再按上面步骤申请。另一环境保持原配置。出现问题可恢复原手工路径；不要撤销仍需回退使用的原授权。发布者不会因此停共享模块或改变硬件模式。

## 为什么会拒绝，如何恢复

| 状态／情况 | 处理 |
| --- | --- |
| 申请已过期 | 回NAS重新申请，再在App刷新确认；请求有效期10分钟 |
| 手机证明失败或不支持 | 核对官方安装渠道、网络和环境；稍后重试。不得绕过验证，必要时沿用已授权手工方式 |
| 中继暂不可用 | 核对完整URL、NAS出站网络与发布者入口是否启用；不要把示例URL当正式入口 |
| 授权被撤销 | 原实例不能靠重复申请／续期恢复；由发布者核对授权，不自动创建无限新实例 |
| 授权到期 | NAS自动续期；到期后7天内可恢复续期，到期期间不发推送，超过宽限由管理员处理 |
| App已连接但推送登记失败 | 刷新推送状态；检查服务版本、手机独立Key及网络，不能仅凭业务连接成功认定推送可用 |
| 有推送界面但无法接听 | 检查手机访问NAS的HTTPS链路、来电状态与音频，推送中继不转发声音 |

自动授权有效90天；NAS每30分钟检查，最多每日尝试一次续期，余期不足60天才延长。续期保持当前凭据，首次签发与续期分别记录；泄露时应单独撤销并按管理员方案重新绑定，不把续期当作秘密轮换。

## 签发数量与台账

同一实例重复开通返回已有授权，不重复签发。每个已验证App证明密钥最多关联3个NAS实例（含已撤销记录）；中继总授权记录上限1000条，申请和推送另有限速。App重装可能产生新证明密钥，因此该额度不是实名用户或物理设备终身总量限制。

发布者台账记录登记昵称、随机NAS实例、签发时间／方式、有效期、领取、续期和撤销。可查看累计首次签发与当前有效数；昵称不能当作已验证真实身份。管理员私有导出后同步本地测试材料，保留人工接收人备注，不公开邮箱、凭据、摘要或证明密钥。

App证明与NAS实例签名可以确认参与绑定的官方App及实例持有权，不能远程证明DJI硬件确实在线，也不能证明每次推送是真实来电。中继保留固定消息、限流和单实例撤销；不要用虚构来电测试连通性。更多接口、安全／留存和回退细节见[中继说明](push-relay.md)、[隐私政策](privacy-policy.md)。
