# 运行、日常测试与回退

安装和参数的唯一通用说明在 [Unraid部署](../deploy/unraid/README.md)，接口以 [API](API.md) 为准。

## 日常状态

1. 先检查服务健康版本与source_commit，再用有效电话会话查status/diagnostics。idle、module_available、SIM就绪、LTE注册分别判断，不从单个ok推出可拨号。
2. 网页管理员签发每手机独立App Key；Key丢失撤销再发，没有取回明文接口。App只保存自己的地址/Key，不输入HiDeck密码。撤销后核对新请求拒绝和关联会话清理。
3. 通话只由当前所有者控制。声音断线/退出会话可能触发结束呼叫，通话中不换Key/会话、不重启服务。模块失联时不能保证远端已挂断，恢复后按原通话ID确认，不盲目再拨。
4. 录音明确同意后才开启。部署时复制关闭示例，不删recording.json：旧服务缺失或损坏时按开启处理。录音文件名含对手号码，文件与历史数据库严格私有。
5. 服务日志只留状态和数值诊断；反代路径访问日志关闭或删去query，避免短信卡片/peer被记录。守护在运行间隙5MiB轮转，长通话时日志可超限，要关注磁盘并维护保留策略。

## 本地日常开发与手机测试

- 源码在同一repo的develop，AI按根版本配置分配新批次并完成本地检查。签名配置、开发IPA、装机记录、私有验收证据放仓库外private/testing，不复制源码到private。
- 用户手机通过对应批次验收后，才合main和建立正式源码标签；再构建正式候选包进TestFlight验证production环境，同一正式构建用于选定海外地区审核和GitHub版本映射；首版范围见 [商店说明](app-store.md)。
- 旧private/legacy是只读历史回退材料，不再作为日常开发入口。public/private划分与develop/main阶段划分是两件事。具体操作以 [发布流程](releasing.md) 为准。
- 安装、前台接入、真实功能与正式推送分别记录结果；通过项见CHANGELOG，未实际执行的项目保持待验。开发测试不自动触发GitHub或商店发布。

## 升级与回退

检查电话idle、旧版本/构建与配置备份齐全 → 用service.sh stop优雅等待 → 替换服务二进制及配套脚本 → start → 核对版本/commit、鉴权与idle。停止返回失败时先处理原进程，不能强行覆盖。

回退按stop/恢复旧二进制和配套脚本/start核验，保留App Key、令牌、短信库、录音、连接历史；不整库覆盖后续数据。HiDeck升级属于另一批兼容变化，先验证后台HMAC及设备/短信响应，不使用latest自动升级。容器部署从DockerMan换Compose前先备份模板，维护者显式停止旧容器，只保留一个模块消费者。

模块重启后临时语音资源可能丢失，服务接通前可按固定SHA与身份恢复；恢复不改变USB/IMS/APN，也不开ADB授权。缺少准备条件时失败结束呼叫，应查只读状态，不通过重复写入“修复”。宿主/模块重启验收须独立记录，不能用进程重启替代。

新iOS App使用新Bundle ID和新的Keychain身份，需重新配置。身份迁移先验证新版，再按用户授权撤销旧客户端凭据、清理旧推送路由和处理旧App。今后同身份覆盖更新保留本机设置，但换身份/删除App后的恢复不能由旧验收推断。回退只用可信同身份签名包；Apple签名、描述文件、APNs和安装对象保存在私有测试资料。

## 故障判断

| 表现 | 优先检查 |
|---|---|
| health可达，设备不可用 | HiDeck健康、设备ID、统一AT占用、USB枚举；不立即写硬件配置 |
| HTTP401 | App Key是否已撤销、是否错用电话会话、短期会话是否重启失效 |
| HTTP403/网页声道失败 | HTTPS来源/Host/端口、Cookie、代理WebSocket升级及SSE缓冲 |
| 注册成功但无声 | 精确模块内核、root ADB目标、资源SHA、ALSA设备；注册不证明音频路由 |
| 手机前台可用但无锁屏来电 | sandbox/production、签名topic、推送授权/设备token；官方relay已有实现，Production需独立TestFlight验收 |
| 提交短信但未送达 | 上游限流/提交状态、SIM服务与接收者确认；避免重复提交 |

向GitHub报问题只提供版本、平台/内核、脱敏状态与复现步骤，禁止上传完整配置、接口原响应、号码、短信、录音、签名文件或日志原包。

日常断音排查：先根据用户反馈的通话时段查音频关联trace，再对照phone.events与服务events。手机send_gap对应后台receive_gap优先查采集/发送；手机节拍稳定而后台停顿优先查传输；后台到达稳定但module_write_slow/underrun优先查模块播放链路。level只辅助判断幅值，不能从自然静音判故障。无需主动拨号、录音或新AT查询。

## 0.1.3 主动断开与短信删除

主动断开会保留最近连接资料及断开标记，清理当前会话和手机推送登记；重连使用设置中已填充的地址/Key。App Key不因此撤销。短信删除是上游历史数据库操作，不是撤回短信或模块AT命令；删除前确认SIM/会话，失败先刷新核对，避免盲目重复。

## 开发与TestFlight并行推送

服务0.1.4按登记环境分流到已有两套中继，参考[中继配置](push-relay.md)及环境样例。开发包保留Sandbox，TestFlight使用Production；切换不需新增模块消费者。部署前电话空闲，备份二进制、来源及env，保留Key／短信／令牌数据；回退恢复该三项。配置与授权检查不能代替两机真实来电和短信验证。
